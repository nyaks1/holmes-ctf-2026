## 1. How flags are actually planted

| Plant style | Typical form | Evidence from writeups |
|---|---|---|
| **Literal in files** | `flag{...}` / `HTB{...}` greppable | Huntress Darcy: `grep -aR "flag{"` finds flag in VCS-like blobs. HTB JS module: flag in page CSS as `HTB{...}` after F12. |
| **Custom encodings** | base64, base32, hex, ROT, Base62, decimal→ASCII | Huntress Sandy: Base64 chunks in AutoIt → nested JSON → `flag{27768419fd176648b335aa92b8d2dab2}`. Webshellz: Base32 in INI comment; Base64 in HTML form field; Base62 password string. Tabby: UTF-16-like separators between letters. Trashcan: recycle-bin file sizes as ASCII codes. |
| **Fragmented / multi-part** | flag MD5 split 8 ways, different delimiters | Huntress BeyBlade: `flag_value_1_of_8-47cb` … reassemble + `flag{`/`}` wrap required. Challenge text *tells* you to wrap. |
| **Runtime-only after deobfuscation** | packed JS, AutoIt, Lua; string appears only post-decode | HTB "Hidden in Plain Sight": packed JS → de4js/UnPacker → concatenated `HTB{j`+`4v45c`+... ; also POST `/serial.php` returns Base64 secret, then hex-decoded key. Huntress "My Hawaii Vacation": Lua infostealer; **flag is `flag.txt` on victim Desktop inside exfil 7z**, not a string in the EXE. |
| **Blockchain / on-chain dead-drop** | hex in contract creation input or storage/bytecode | HTB Uni CTF Warren Buffer: pcap → hex in User-Agent → link → b64 jpeg → ETH address → **contract creation input / decompiled vars hex→string** = `HTB{1a4b20ec17323f20909c224614308f09}`. On-chain payload *is* the wrapped flag or material that hex-decodes to it. |
| **Config / nested blobs** | encrypted zip + password in strings; PE resources; API JSON | Huntress "I Forgot": Volatility memmap PID → strings find 7z password → binwalk embedded zip → RSA/AES decrypt `flag.enc` → `flag{fa838...}`. |
| **IOCs ≠ flags (Sherlock questions)** | answers are hash, XOR key, endpoint, service name | HTB Sherlock Lockpick3.0 questions: malware MD5, **XOR string used for obfuscation**, API endpoint for key, upload endpoint, service name — *not* `HTB{NAPOLEON}` style wraps of narrative secrets. |

### Critical implication for TrustSettle / Holmes 0/10
Wrapping recovered secrets (`HTB{NAPOLEON}`, `HTB{SR-4821}`, contract addresses) fails when:
1. The planted flag is a **different string** (MD5-like `flag{32hex}`, leet `HTB{...}` only after Lua deobfuscation, or a multi-part assembly).
2. Sherlock/multi-flag UI expects **bare question answers** or **exact planted tokens**, not analyst-made wraps.
3. The flag lives in **exfil/victim artifacts or chain storage**, not as `AUTH=`/coords in the decrypt log.
4. Format is `flag{...}` not `HTB{...}` (Huntress-style) or hex-inside-HTB like Warren Buffer.
5. A **cryptographic or encoding step remains** after "decrypt" (another base64/hex/XOR layer; fragments to concat).

## 2. Extraction methodology used by writeup authors (prefer no execution)

Ordered from least to most invasive — writeups almost always start static:

1. **File type / inventory** — `file`, tree, binwalk; look for nested archives, PE, Lua/JS.
2. **String hunting** — `strings -n N`, `grep -aR "flag{"`, `grep -i htb`; also search `flag`, `HTB`, `key`, `password`, `decrypt`.
3. **Encoding recognition + decode** — CyberChef: From Base64/32/36/58/62, hex, ROT13; try multiple recipes. Eyeball base64 padding; hex in headers/UA/config.
4. **Static deobfuscation** — beautify (Prettier); unpackers (UnPacker, de4js Auto Decode); Exe2Aut for AutoIt; for Lua/Luraph: identify VM/bytecode, dump tables, hook string decrypt *in a sandbox or reimplement decryptor offline*; do **not** run the sample on the analyst host (Huntress notes players who did tripped Defender on Sandy.exe).
5. **Network / chain off-box** — follow C2 URLs, credentials found in malware; query blockchain explorers for creation tx input, storage, events; decompile bytecode → hex-to-string variables (Warren Buffer). Offline decrypt of on-chain blobs is preferred over "running" malware.
6. **Memory / disk forensics** — Volatility memmap dump PID, strings/binwalk embedded files; registry tools for hive answers; recycle-bin parsers; notepad TabState `.bin`.
7. **Emulation when necessary** — any.run / isolated VM for behavioral path (Hawaii Vacation used anyrun to see curl/7z/exfil), then recover **artifacts the malware would exfil** (stolen flag.txt), not just code constants.
8. **Assemble / wrap only when evidence demands** — BeyBlade text says wrap MD5 in `flag{}`; Warren Buffer on-chain bytes already include or decode *into* `HTB{...}`. **Do not invent wraps of IOCs.**

### Lua / Luraph-specific notes (second-stage path)
- Obfuscated Lua (Luraph-like) typically hides strings in encrypted constant tables + VM dispatch; literal `HTB{` will not appear on disk.
- Flag-like plaintext often appears only after: constant-table decrypt, bytecode decompile (luajit `-bl` / unluac-style), or emulating the string decoder offline.
- CTF authors plant either (a) the flag string as one decrypted constant, (b) a key/config that *is* the flag body, or (c) nothing in Lua — the flag is on the C2/victim side.
- "Never run obfuscated code" is an explicit HTB lesson (deobfuscated flag text `HTB{n3v3r_run_0bfu5c473d_c0d3!}`); static unpack is the intended path.

### Blockchain planting patterns
- Flag body as **ASCII/hex bytes** in contract constructor input or storage slots.
- Multiple **uint/string variables** in decompiled bytecode that hex-decode to `HTB{...}`.
- Decryption key/config on-chain; plaintext flag produced by applying that key to another blob — but the **submit string** is usually the fully formed `HTB{...}` / `flag{...}`, not intermediate AUTH/coords.
- Analyst mistake pattern: treating operational secrets (AUTH=NAPOLEON, coordinates) as flag bodies and wrapping them; writeups show the wrap content is usually a **hash or decoded hex blob**, not a human-readable codename unless that exact string was planted with the prefix.

## 3. What to re-check on TrustSettle (actionable, derived)

- Re-scan all files for `flag{`, `FLAG`, base64 blobs, hex constants — not only `HTB{`.
- After Luraph/Lua decrypt: search decrypted tables for `HTB{`, `flag{`, 32-hex MD5-like tokens.
- Treat on-chain decrypt output as **layers**: AUTH/coords may be stage-1; look for a second encoding of a flag-shaped token.
- Do not submit IOC wraps; submit only strings that **appear with a flag prefix** after decode, or answers matching Sherlock question style (hash / XOR key / endpoint) if UI is question-based.
- Compare candidate formats: `HTB{md5}`, `HTB{leet}`, bare MD5, `flag{md5}`, multi-part concat.
